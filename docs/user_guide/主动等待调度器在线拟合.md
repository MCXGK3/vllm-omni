# 主动等待调度器：在线采样与自动拟合

## 功能概览

代价感知调度器现在支持四种预测器模式：

| 模式 | 是否采样 | 是否自动拟合 | 是否用于调度 |
|---|---:|---:|---:|
| `static` | 否 | 否 | 立即使用仓库内原有固定系数 |
| `collect` | 是 | 是 | 否，只进行影子采样和拟合 |
| `learn` | 是 | 是 | 样本不足时不做代价决策；拟合完成后自动启用 |
| `fitted` | 否 | 否 | 加载已经保存的拟合模型；没有可用模型时不做代价决策 |

默认仍为 `static`。本次将主动等待的默认最小平均延迟收益提高到 10 ms，
因此没有设置新环境变量时会比旧实现更保守。

## 推荐启动方式

首次部署时建议先使用 `collect`，确认样本覆盖和误差后再切换到 `fitted`；如果希望在一次长时间服务中自动完成切换，可以直接使用 `learn`。

```bash
export VLLM_OMNI_COST_AWARE_SCHEDULER=1
export VLLM_OMNI_COST_MODEL_MODE=learn
export VLLM_OMNI_COST_MODEL_PATH=/home/cost_models/qwen3_omni_cost_model.json

# 至少积累多少条样本后首次拟合。默认 32，正式实验建议 64 或更多。
export VLLM_OMNI_COST_MODEL_MIN_SAMPLES=64

# 新增多少条样本后重新拟合。默认 8。
export VLLM_OMNI_COST_MODEL_REFIT_INTERVAL=8

# 某种执行路径至少出现多少次，才会尝试拟合该路径。默认 16。
export VLLM_OMNI_COST_MODEL_MIN_PATH_SAMPLES=16

# 每条路径至少保留多少条时间靠后的样本做验收。默认 3。
export VLLM_OMNI_COST_MODEL_MIN_VALIDATION_SAMPLES=3

# Thinker forward 完成后到请求可被 Talker 调度之间的交付余量，默认 10 ms。
# 它覆盖输出后处理、IPC 排队/传输和下游请求接收。
export VLLM_OMNI_FUTURE_DELIVERY_MARGIN_MS=10

# 小于该值的等待不执行，也不消费 future hint，默认 0.1 ms。
export VLLM_OMNI_COST_AWARE_MIN_WAIT_MS=0.1

# 每个请求平均完成时间至少需要改善多少才允许等待，默认 10 ms。
export VLLM_OMNI_COST_AWARE_MIN_GAIN_MS=10

bash scripts/start_vllm_omni.sh scripts/bench.sh
```

在线拟合会自动启用异步 CUDA Event 计时。如果显式设置了下面的变量，应使用 `cuda_event`，不要使用 `cpu`：

```bash
export VLLM_OMNI_REQUEST_GANTT_TIMING_MODE=cuda_event
```

## 拟合过程

每次 AR forward 会保存本批请求在执行前的特征，并记录一对 CUDA Event。事件不会立即同步；后续 forward 开始或进程退出时，代码只读取已经完成的事件。因而正常运行时不会为了计时调用 `torch.cuda.synchronize()`。

每种执行路径分别拟合下面的模型：

$$
T = \boldsymbol{\beta}^{\mathsf T}
\left[
1,\frac{N}{10^3},\frac{A}{10^6},\log_2(1+B),
\frac{M}{10^3},\frac{C}{10^3},\frac{S}{10^3},D,P
\right].
$$

其中：

- $N$：本批实际调度 token 总数；
- $A$：causal attention pair 数，单请求贡献为 $q c + q(q+1)/2$；
- $B$：批内请求数；
- $M$：批内最大的 $c+q$；
- $C$：所有请求历史 context token 之和；
- $S$：所有请求处理后 sequence length 之和；
- $D$：decode token 数；
- $P$：包含 prefill token 的请求数；
- prefill、decode、chunked prefill、普通 mixed 和 piecewise mixed 使用不同的系数，不共享斜率。

Thinker 和 Talker 在不同进程中分别采样、分别拟合，模型文件以 stage ID 保存两套模型。每个 stage 内又按执行路径分别建模。拟合采用带正则项的岭回归，以降低样本共线性造成的系数剧烈波动。

每次拟合按时间顺序把某条路径最后 20% 的样本留作验证集。只有在线模型的验证集 MAE 不高于原固定公式，该路径才会被 scheduler 接受。可以使用 `VLLM_OMNI_COST_MODEL_ACCEPT_RATIO` 调整验收比例，默认值 `1.0` 表示在线模型至少不能比固定公式差。

## 生成文件

假设设置：

```bash
export VLLM_OMNI_COST_MODEL_PATH=/home/cost_models/qwen3_omni_cost_model.json
```

则会得到：

- `/home/cost_models/qwen3_omni_cost_model.json`：Thinker/Talker 系数、样本数、路径覆盖、MAE、RMSE 和 R²；
- `/home/cost_models/qwen3_omni_cost_model.json.stage0.samples.jsonl`：Thinker 原始样本；
- `/home/cost_models/qwen3_omni_cost_model.json.stage1.samples.jsonl`：Talker 原始样本；
- `/home/cost_models/qwen3_omni_cost_model.json.lock`：多进程更新模型时使用的文件锁。

模型文件通过临时文件加 `os.replace()` 原子更新。Scheduler 最多每 250 ms 检查一次文件修改时间，发现新模型后无需重启即可加载。

## 安全切换规则

`learn` 模式在达到最小样本数前，不执行主动等待和基于预测时长的 admission 限制，仍由原 scheduler 正常处理请求。

调度器只会使用满足下面条件的未来请求提示：

$$
T_{\min} \leq t_{\text{ready}} - t_{\text{now}} \leq T_{\text{window}}.
$$

已经过期的提示不会进入收益计算，也不会被标记为已经等待。发布给下游的 `ready_at` 等于上游预测 forward 时间再加 `VLLM_OMNI_FUTURE_DELIVERY_MARGIN_MS`，避免把“上游 GPU 完成”误当成“下游已经可以调度”。

等待收益按请求平均完成时间计算。多个未来请求会被视为一个自然批次，不再把单请求预测时间逐项相加；当前批中的每个请求都会计入等待惩罚。对于不同 ETA 的 future hint，调度器枚举按到达时间排序的前缀，只选择平均延迟收益最大的前缀，并等待到该前缀最晚的 ETA。

即使总样本数已经足够，如果当前执行路径样本不足，或者该路径没有通过样本外误差验收，它仍会回退到原固定公式。这样可以避免服务启动后最先积累的大量 decode 样本被错误地用于推断 prefill 或混合批。

日志中出现以下信息，表示某个 stage 已完成拟合并被 scheduler 加载：

```text
Online cost model fitted stage=0 samples=64 accepted_paths=['decode_full']
Online cost model activated stage=0 samples=64 paths=['decode_full']
```

## 实验建议

自动拟合只能学习已经出现过的工作负载。正式启用前，采样阶段至少应覆盖：

1. 小、中、大 token 数的普通 prefill；
2. 不同 chunk 长度和不同历史 context 的 chunked prefill；
3. 纯 decode；
4. prefill 与 decode 混合批；
5. 不同请求数和不同长度分布；
6. Talker 中 CUDA Graph、piecewise graph 和 eager 路径的边界区域。

如果模型、TP 配置、GPU 型号、最大批 token 数或关键 kernel 配置发生变化，应使用新的模型路径重新采样，避免复用不再匹配的系数。
